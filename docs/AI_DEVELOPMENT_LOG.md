## 3. Workflow Decisions & Implementation Log

### Decision Log 1: Dataset Provenance Strategy
- **AI Proposal**: Download Lending Club dataset (`wordsforthewise/lending-club`) via `kagglehub` / curl, with an automated fallback generator that creates statistically matched prototype distributions if authentication blocks downloading.
- **Human Requirement**: Ensure clear disclaimers that Lending Club is prototype data because the competition organizer dataset was unavailable at implementation time.
- **Outcome**: **ACCEPTED**. Built `src/ingestion/download.py` with multi-tier fallback and prominent provenance banners across README, dashboard, and reports.

### Decision Log 2: Canonical Adapter Architecture
- **AI Proposal**: Directly couple models to Lending Club column names for brevity.
- **Human / Architectural Decision**: **REJECTED**. All ML components must be strictly decoupled from Lending Club specifics via a canonical schema (`loan_static_attributes.csv`, `loan_monthly_performance_*.csv`) so that replacing Lending Club with the organizer dataset requires only updating `LendingClubAdapter`.
- **Outcome**: **ACCEPTED**. Implemented clean `LendingClubAdapter` and `src/config/schema.py`.

### Decision Log 3: Target Leakage Prevention & Temporal Validation
- **AI Proposal**: Use standard 80/20 train/test split.
- **Human / Engineering Decision**: **REJECTED**. Random row-level splitting causes catastrophic data leakage in loan-month panel data.
- **Outcome**: **ACCEPTED**. Implemented `TimeAwareSplitter` enforcing strict chronological cutoffs and loan ID group isolation. Targets are calculated strictly from forward-looking future time steps ($T+1 \dots T+12$).

### Decision Log 4: Grounded LLM Copilot & Offline Independence
- **AI Proposal**: Use OpenAI or Gemini API for generating loan underwriting summaries and copilot responses.
- **Engineering Decision**: System must operate 100% offline without requiring external API keys. Core predictions must be non-LLM tabular machine learning.
- **Outcome**: **ACCEPTED**. Built `GroundedReviewerCopilot` with deterministic grounded synthesis over codified data dictionaries and validation rules, accompanied by `CopilotAuditLogger` in JSONL.

## 4. Accepted vs. Rejected Suggestions

| Component | Proposed Approach | Status | Rationale |
| :--- | :--- | :--- | :--- |
| **Model Stack** | Use LightGBM + Logistic Regression with Probability Calibration | **ACCEPTED** | Provides high tabular predictive power, interpretable linear baselines, and calibrated probability estimates. |
| **Imbalance** | Blind Random Over-Sampling (SMOTE) on temporal panel | **REJECTED** | SMOTE on time-series panels introduces synthetic temporal inconsistencies. Replaced with class weighting and sample weighting. |
| **Transition Model** | Pure Cox Proportional Hazards regression | **MODIFIED** | Implemented empirical Markov transition matrices ($P(S_{t+1}\|S_t)$) with roll-forward powers ($T^h$) for explicit multi-state migration curves. |
| **Anomaly Engine** | Isolation Forest only | **MODIFIED** | Upgraded to a hybrid composite system combining deterministic business rules, ML Isolation Forest, and servicer tape reconciliation conflicts. |

## 5. Lessons Learned & Governance Takeaways
1. **Schema Decoupling is Essential**: Separating source data from canonical representations protects the pipeline against upstream data format shifts.
2. **Probability Calibration Matters**: In credit risk and loss forecasting, raw tree scores are often miscalibrated. Platt and Isotonic scaling ensure that a predicted 5% default rate corresponds to an actual 5% empirical loss.
3. **Auditable AI Logs**: Logging every query, retrieved context, and reviewer recommendation to `artifacts/logs/copilot_audit_log.jsonl` provides transparency and compliance traceability for credit auditing.
